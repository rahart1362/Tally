One correction to the report, trusted the code per rule 8: the report's proposal step 3 describes
the named interstitial's primary button as "Ask My School" reusing the *share flow*. Read
literally, `SchoolNotEnabledView`'s "Ask My School" is a `ShareLink` — but SwiftUI's `.alert`
actions are not documented to host a `ShareLink` reliably (and this host cannot verify it on a
device). Implemented instead as: the named interstitial's primary button reuses the "Ask My
School" **string** verbatim and lands on `SchoolNotEnabledView` itself (via
`AppModel.checkMySchool()`), where the *existing*, already-shipped `ShareLink` lives — so the
share flow is reused by navigating to its one home, not by re-embedding it in an alert. This also
satisfies the report's step 4 ("fix 'Check My School' to push `.schoolNotEnabled(school:)`
directly... so the action actually goes where its label promises") in the same stroke: the
former "Check My School" button *is* the button that now reads "Ask My School" once a name is
known, and its destination is fixed regardless of label.

## Implementation

1. **Storage** (steps 1-2 of the proposal): a new pre-account, non-sensitive, non-account-scoped
   preference, following the app lock's own pattern exactly:
   - `NotEnabledSchoolPreferenceStoring` (protocol) + `InMemoryNotEnabledSchoolPreferenceStore`
     (default) — `packages/TallyAppleKit/Sources/TallyFeatures/Onboarding/SchoolSearch/NotEnabledSchoolPreference.swift`
     (new file), mirroring `AppLockPreferenceStoring`/`InMemoryAppLockPreferenceStore`
     (`AppLockPorts.swift`).
   - `FileNotEnabledSchoolPreferenceStore` (concrete) —
     `packages/TallyAppleKit/Sources/TallyPlatform/FileNotEnabledSchoolPreferenceStore.swift`
     (new file): a plain UTF-8 text file via `ProtectedFile.prepareDirectory`/`atomicWrite`/
     `read`/`remove` (never `Data.write(to:` directly; never Keychain — the value is not
     sensitive the way the lock flag is). Wired at `<StoreLocation.root>/not-enabled-school.txt`
     in `apps/TallyiOS/Tally/AppEnvironment.swift`.
   - `AccountEnvironment.notEnabledSchoolPreferences` (new member, defaulted to the in-memory
     store so every existing call site — 9 test files + the composition root — compiles
     unchanged).
   - `AppModel.notEnabledSchoolName` (cached, `public private(set)`), loaded concurrently with the
     account resolve in `launch()` (`async let`, off the `Launch.GlancePaint` critical path — read
     only several taps later, in Settings → Subscription). `recordNotEnabledSchool(_:)` (called
     from `WelcomeFlowView`'s `onSelectNotEnabled`) persists and caches at once;
     `clearNotEnabledSchool()` (private) is called from both `signOut()` (Sign Out & Erase) and
     the private `completeSignIn(_:storeRoot:)` (the one place either sign-in path — through
     sample mode or direct — reaches a real `.signedIn` account).
   - **Test-isolation fix**: `LaunchTestHooks.eraseEverything` now also clears this preference (it
     did not exist before). Without this, the simulator's container persisting between UI test
     methods (this file's own documented behaviour for the app lock) would leak a stored school
     name from one test into the next test's fresh sample mode.

2. **The interstitial's two states** (step 3): `SampleInterstitialState` (new, pure `enum`:
   `.generic` / `.named(String)`, trimming/blank-guarding the stored value) in
   `SubscriptionSettingsView.swift`, unit-testable apart from the view. The view's `.alert` now
   branches on it: `.generic` is the exact, byte-for-byte unchanged code path (same strings, no
   new identifiers) — the App-Review path. `.named` shows the new interpolated message
   (`L10n.Subscription.interstitialMessageNamedSchool(school:)`) and swaps "Check My School" for
   the *existing* `L10n.Onboarding.SchoolSearch.askMySchool()` string, with new identifiers
   (`subscription.interstitial.askMySchool`, `.continue`) added only to this new branch — the
   unmodified fallback branch keeps zero identifiers, so the pre-existing text-matched tests
   (`PaywallUITests.openPaywallThroughTheInterstitial`, which finds "Check My School"/"Continue"
   by their literal label) are provably untouched.

3. **"Check My School" → the remembered school's page** (step 4): `AppModel.checkMySchool()`
   (new) — the same root switch as `exitSample()`, except when a name is stored it first sets
   `pendingWelcomeRoute = .schoolNotEnabled(school:)`. `WelcomeFlowView.init` (now explicit, was
   implicit/memberwise) consumes-and-clears it once
   (`AppModel.consumePendingWelcomeRoute()`) to seed `path`, so only this one action ever lands on
   that page — the plain "Exit Sample Data" banner still calls `exitSample()` directly and leaves
   no destination (a dedicated test proves this: `exitSampleLeavesNoDestination`).
   `SettingsView`'s `onCheckMySchool` closure now calls `app.checkMySchool()` instead of
   `app.exitSample()`.

`PaywallPlacement.shows`/`needsInterstitial` — untouched (`git diff` against
`PaywallPlacement.swift`: empty).
