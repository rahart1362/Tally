- Read the brief (`pmo-kit/briefs/pmo-age1-prompt.md`), `pmo-common-rules-v2.md` in full (incl.

  `matrix.md` §0–§2 and the duty table, `dossier.md` §2, §6, §9, §12. Never committed; not copied
  into this worktree.
- Apple's own documentation pages (`developer.apple.com/documentation/...`) render through
  JavaScript and return only a page title to a plain-text fetch. Found that the same URL with a
  literal `.md` suffix serves the raw Markdown symbol/article page (e.g.
  `.../declaredagerange/agerangeservice.md`) — this is how every API surface in this PR was
  verified, including Apple's own worked sample code in "Requesting people's age range
  information in your app" and "Implementing age assurance and permissions" (both read in full).
- Two API deviations from the backlog's assumption, found this way and recorded in the code and
  the PR:
  1. `AgeRangeService.ParentalControls.significantAppChangeApprovalRequired` is **deprecated**;
     the current signal is `AgeRangeService.requiredRegulatoryFeatures` (iOS 26.4+, a
     `Set<RegulatoryFeature>`). `DeclaredAgeRangeAdapter` prefers it and falls back to the
     deprecated flag only below 26.4 (the project's floor is 26.0, F16).
  2. `isEligibleForAgeFeatures`'s symbol page shows a plain `Bool`, but every one of Apple's own
     worked examples calls it `try await`. Written as `try await`, matching the examples; the
     `scope=only` run is where this gets checked against the real SDK.
  3. PermissionKit's "Significant Change API" the backlog named is `SignificantAppUpdateTopic` +
     `AskCenter` (iOS 26.2+) — not the framework's headline iMessage communication-safety topic.

## Implementation (additive; rule 9)

- `TallyDomain/AgeAssurance/AgeAssurance.swift`: every pure decision type and function —
  `AgeCategory`, `SignificantChangeRequirement`, `AgeAssuranceSignal`/`Outcome`,
  `SignificantChangeConsentOutcome`, `AgeGate`, `AgeRequestTrigger`/`Policy`,
  `AgeRatingChangeDetector`. No I/O, no Apple framework — Linux-testable (EB-01(h)).
- `TallyStore/AgeAssuranceStore.swift`: `AgeRequestRecord` (the **one** persisted field,
  `lastRequestedAt: Date`) and `SignificantChangeVersionState` (two non-age values), both plain
  JSON like `accounts.json`, same pattern as `AccountDirectoryStore`.
- `TallyFeatures/AgeAssurance/`: the ports (`AgeAssuranceRequesting`, `SignificantChangeConsenting`,
  `AppStoreAgeRatingReading`, the two store protocols) as `WebAuthPresenting`/
  `AppLockPreferenceStoring` declare theirs; `AgeAssuranceModel` (the `@MainActor @Observable`
  orchestrator, built like `AppLockModel`); `AgeRestrictedView`/`AgeRestrictedPresenter` (the
  neutral screen, built like `SchoolRevokedNoticeView`/`SchoolRevokedNoticePresenter`, but with no
  escape button — the point is to block).
- `TallyPlatform/`: `DeclaredAgeRangeAdapter`, `SignificantChangeConsentAdapter`,
  `AppStoreAgeRatingAdapter`, `AgeRequestRecordFileStore`/`SignificantChangeVersionFileStore`
  (wrap the TallyStore structs with `@concurrent`, as `KeychainAppLockPreferenceStore` wraps the
  Keychain).
- Wiring: `Tally.entitlements` (+`com.apple.developer.declared-age-range`, already allow-listed);
  `LaunchResolution.isFirstLaunchAfterInstall` (threads `LaunchBootstrapper`'s existing
  `reconciled` flag out, previously discarded); `AppModel.ageAssurance` + three call sites
  (`apply(_:)`, `showFirstSyncPaywallIfDue`, `showPaywall(for:)`); `RootView`'s `.signedIn` case
  gets one more `.background` presenter, same shape as the school-revoked one; `AppEnvironment
  .live()` composes the real adapters over the account-independent store root (same root
  `accounts.json` already uses).
- New strings: `L10n+AgeAssurance.swift`, 2 keys (`ageAssurance.restricted.title`/`.body`), en +
  es `needs_review`, added directly to `Localizable.xcstrings` in alphabetical position (matched
  Xcode's own sort order so the diff is minimal) — `check_string_catalogs.py` passed clean
  (712 keys now; was 710).
- `check_release.py`: `age_assurance_checks()` (pure, dict/text in — mirrors `flow_checks`'
  testability) — `REL.age-assurance.entitlement-present` and `REL.age-assurance.no-age-on-disk`
