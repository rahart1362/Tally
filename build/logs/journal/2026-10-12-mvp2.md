## CI run #2 (`scope=quick`, run 38280762497) — 2 of 3

Compiled clean this time. Job overall still **failure** (`Run TallyAppTests and TallyUITests`,
`TallyAppTests on the deployment-floor runtime`), but the accessibility suite's own failures are
the informative part. Nearly every screen in every class failed with exactly **one** terse,
Apple-generated message — `Contrast failed`, `Dynamic Type font sizes are partially unsupported`,
or (WhatIf only) `Hit area is too small` — and every failing test stopped there: e.g. `testWelcome`
(Light class, meant to run both the std and the AX5 audit in one method) shows two near-identical
~15 s failures, far too short to have reached the second (AX5) `auditScreen` call at all.

**Root cause, found by reading `TallyUITestCase.setUpWithError` again:** it sets
`continueAfterFailure = false` (every suite inherits it). When `performAccessibilityAudit`'s issue
handler returns `false` (not waived), it records that as a failure *immediately*, through
whatever mechanism backs `continueAfterFailure = false`'s abort — not a thrown Swift error this
method's own `do`/`catch` can intercept (the same way an `XCTAssertTrue` failure skips the rest of
a test method regardless of surrounding `try`/`catch`). Consequence: the *first* unwaived issue
ended the test on the spot — no later issue in the same audit call was ever found, no JSON ever
got attached (the attach call is after the `do`/`catch`, which this abort skips entirely), and
this method's own, more informative `XCTAssertTrue` message never ran either — only Apple's own
terse one-liner did. `FamilyUITests`' two existing audit tests passed cleanly in this same run
(no issue ever triggered the abort there), which is consistent, not contradictory.

**Fix**: `runA11yAudit` now saves `continueAfterFailure`, sets it `true` for the span of the
`performAccessibilityAudit` call (so the handler runs for every issue, not just the first), then
restores the original value immediately after, before its own assertion. Also added an evidence
export step to `release-gate.yml`'s accessibility-audit section (`xcresulttool export
attachments`, kept to `*audit*.json` only, uploaded as artifact `a11y-audit-evidence`) — this
host has no Xcode, so the only way to actually read the `<screen>-<variant>-audit` JSON this
suite attaches is to have CI extract it on the macOS runner and hand back plain files.
**Verified locally again**: self-test 24/24, debug-symbol check 0 problems, braces 155/155, YAML
and every `run:` block's bash syntax still clean.
