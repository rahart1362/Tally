## Step 2 — item 0, the fixed-date test hook

Traced the real clock seam by reading `LaunchTestHooks.swift`, `AccountEnvironment.swift`,
`SampleDataGateway.swift`, `SampleSession.swift`, `HomeModel.swift`, `HomeProjector.swift`,
`CalendarProjection.swift` and `AppModel.swift`. Found the actual bug: `AppModel.enterSample()`
built `SampleSession(logger: logger)` and `HomeModel(source: ...)` with neither given `self.clock`
— both defaulted to a *fresh* `SystemDateProvider()` of their own, never `AppModel`'s own `clock`
(itself already wired from `accountEnvironment?.clock`). So even though `AccountEnvironment.clock`
could already be overridden by a test hook, Sample Data (and Parent Mode, `enterSampleFamily()` →
`FamilyModel.sample`, the same bug) never read it. `TallyFormat`/`ScreenFormatter`/`CalendarBuilder`
all take an explicit `now`, correctly threaded from `HomeProjector.project(now:)` — not seams that
needed a fix themselves, just the path confirming where `now` already flows once `HomeModel`'s own
clock is right.

Added `LaunchTestHooks.Key.fixedNow` (`-TallyTestHooks.fixedNow <ISO-8601>`, parsed with
`ISO8601DateFormatter`), a `FixedDateProvider: DateProviding` stand-in, and
`AccountEnvironment.replacingClock(_:)`. `LaunchTestHooks.configure(_ environment:)` applies the
fixed clock first, and the replay-gateway branch now captures `configured.clock` (post-override)
instead of `environment.clock`. Fixed `AppModel.enterSample()`/`enterSampleFamily()` to thread
`self.clock` through. None of this changes Release behaviour: the whole hooks file compiles only
under `DEBUG || TALLY_TEST_HOOKS`, and `AppModel.clock` already equals `SystemDateProvider()` with
no hooks active.

Added `TallyUITestCase.defaultTestHookArguments` (a `class var`, same pattern as
`currentLocaleArguments`), empty by default; overridden with the new
`TestHooks.fixedNowWednesday` (`2026-10-14T12:00:00Z`, a Wednesday, chosen for representativeness)
in `AccessibilityAuditUITests`, `-DarkUITests`, `-ContrastUITests` and `AuditTourUITests`. Every
other suite's launches are untouched. `ToDoUITests` is deliberately NOT overridden — the brief
names only the a11y audit and the tour.

Verified locally: `make lint` (0 violations, 289 shipping-code files, including the three touched
app files), `check_localizable_literals.py` / `check_string_catalogs.py` /
`check_debug_only_test_symbols.py` (all PASS — no new strings, no new DEBUG-only test symbols
outside `#if DEBUG`). No Xcode on this host, so CI is the only remaining check.

## Step 6 — item 1's scroll fix: broken, then fixed, on real CI

**Run 38997367491** (scope=only, real/fixed code, `ToDoUITests/testBatchMarkDoneKeepsAMidListRowOnScreen`):
FAILED — "did not scroll past the large title — 'Missing & overdue' is still hittable" — but the
dumped hierarchy showed NEITHER header anywhere on screen; all `todo.row` elements visible were
December-due ("Later" section). Root cause: a full `app.swipeUp()` travels nearly the whole screen
(~700 pt on this 874 pt device) in one gesture — enough to jump straight past the ~300 pt gap
between "Missing & overdue" and "Due this week" in a single swipe. All 10 swipes were spent (confirmed
by log: 10 `Swipe up` entries), landing deep past both headers; the compound "both hittable" stopping
condition never matched again because `weekHeader` had overshot too, not because nothing scrolled.
Log: `pmo-audit/.build-audit/mvp2i/run-38997367491-todo-overshoot-logs/`.

**Fix**: replaced the full-swipe loop with small nudge drags (`XCUICoordinate` press-drag, about a
sixth of the screen's own height each — the same primitive `bringClearOfTheTop` already uses) and a
position-based stopping condition (`weekHeader`'s own top near the nav bar's, by then collapsed,
bottom edge), checked after every nudge. Removed the now-unused `scrollUntil` helper added in step 3
(nothing else needs it; the nudge loop is scoped to this one test).

**Run 38999451821** (scope=only, same test, fixed nudge logic): PASSED, 82.9 s (default device).
This is the GREEN half of the red/green proof, on the real code.
