## Step 2 — SEC1-10 (Siri/Shortcuts answering past App Lock)

`apps/TallyiOS/Tally/Intents/DueIntents.swift`: added `authenticationPolicy` to
`WhatsDueNextIntent`/`WhatsDueTodayIntent`.

Looked up Apple's App Intents documentation for the exact policy (this host cannot compile-check
the symbol): `IntentAuthenticationPolicy.requiresAuthentication` is satisfied by *any* one
unlocked device in the request — Apple's own docs say it would still let the intent's code run on
a locked iPhone if the request came from an already-unlocked paired Apple Watch, which is the
report's "roommate holds the locked phone" scenario by another route. `.requiresLocalDeviceAuthentication`
is Apple's documented case for "data that's only available when the current device is unlocked"
— exactly `GlanceReader`'s CUFA-protected disk read. Used the stricter, more precise policy (the
brief allows "the report's equivalent"); recorded the reasoning in the code comment.

Verdict recorded for the other App Intents per the brief's instruction: "Refresh Tally" answers
with a status word only (`RefreshAnswer`, no title/grade); "Mark Done" takes only an opaque ID,
is not discoverable, and the system already disables widget buttons on a locked device; the Focus
filter's `perform()` only (de)activates a filter built from courses chosen earlier while
configuring it (in Settings, unlocked) — reveals nothing at call time. No change needed for any
of the three. Added a test asserting both policies directly (`WidgetIntentsTests.swift`).

## Step 6 — SEC1-01 (sign-out's SecItemDelete status discarded)

## Step 8 — SEC1-02 (revoke with a possibly-expired token, result ignored) and SEC1-03 (token not bound to account)

`SignOutUseCase.swift`: before revoking, checks `credential.isAccessTokenUsable(now:)`; if not,
runs one refresh (`refreshedForRevoke`, best-effort, never saved — the credential is deleted a few
lines later regardless) and revokes with whichever token it ends up with. Logs
`.signOutRevoked(ok:)` — `ok` is the refresh/revoke sequence producing a 2xx, not just "no
transport exception". Basic variant only, as the brief specified: no new user message (the
report's owner-approval-gated copy is **recorded as an open item** below). Added `now`/`logger`
parameters (both defaulted, so every other caller is unaffected); `AccountSignOut.swift` passes
`environment.clock.now()`/`environment.logger` (one line). New `LogEvent.signOutRevoked` case,
threaded through `PlatformLogEvent`. 2 new tests in `SignOutUseCaseTests.swift`: an expired token
refreshes first (asserts the revoke request's `Authorization` header carries the *refreshed*
token, and the logged outcome) and a still-usable token skips the refresh entirely.

`AccountSessionFactory.swift`: `gateway(for:environment:)` now only hands the `TokenCoordinator`
an `initial` credential when it is bound to the account's own host and Canvas user ID
(`matchingCredential`, extracted pure for testing). Documented in the code that this cannot
actually differ yet (one credential, one record, written from each other at sign-in — D5), so this
is defense in depth with no behaviour change today. 4 new tests in `AccountRuntimeTests.swift`.
