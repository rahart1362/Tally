## SEC1-09: App Group minimisation

- Design: two roots, not one. `AccountEnvironment.storeRoot` keeps its name but now resolves the
  app's own Application Support (`StoreLocation.privateRoot()`), never the App Group; a new
  `AccountEnvironment.sharedRoot` resolves the App Group container
  (`StoreLocation.sharedRoot(appGroupID:)`), or `nil`. `SnapshotStore` and `AccountPurger` gained
  an optional `sharedRoot` parameter, defaulting to `nil` (= `root`), so every existing call site
  and test that doesn't pass it keeps the exact pre-fix, single-root behaviour — only the
  production composition root (`AppEnvironment.live()`) and the places that build a *real*
  `SnapshotStore`/purge for the signed-in account (`AccountSessionFactory`, `AccountSignOut`,
  `LaunchBootstrapper`, `LaunchTestHooks.seedFlagship`/`eraseEverything`) thread the real
  `environment.sharedRoot()` through. `accounts.json`, the snapshot, user state, the sync ledger
  and the refresh record all move for free once `storeRoot` points at the private location — only
  the glance (`SnapshotStore`'s `glanceLayout`) needed new plumbing.
- Added `StoreMigration.migrateIfNeeded(privateRoot:oldCombinedRoot:)` (new file,
  `TallyCore/Sources/TallyStore/StoreMigration.swift`): moves an existing install's
  `accounts.json`, install sentinel and every account's non-glance files from the old combined
  root to the new private one; the glance never moves (it was already in the App Group). Wired
  into `LaunchBootstrapper.resolve()` as step 0, strictly before `reconcileInstallIfNeeded` — an
  upgrading install's sentinel has to land at the new root first, or step 1 would read it as a
  fresh install and shred every vault key on the very launch meant to migrate them. No-op whenever
  the two roots are the same directory (App Group never configured) or the private root already
  has `accounts.json` (already migrated).
- `AuditTourUITests`'s widget-render leg (`TestHooks.seedFlagship`) reads the real App Group
  container from a separate process (the widget extension), so `LaunchTestHooks.seedFlagship` and
  `.eraseEverything` had to pass `environment.sharedRoot()` through explicitly, not rely on the
  default — checked by reading `AuditTourUITests.swift`'s `seedFlagshipAccount()` call sites and
  `.github/workflows/audit-tour.yml`'s widget-capture leg.
- Updated every doc comment that claimed a single "App Group" root for `storeRoot`
  (`AccountEnvironment.swift`, `StoreLocation.swift`, `AccountPurger.swift`, `UserStateAccess.swift`,
  `LaunchBootstrapper.swift`, `AppEnvironment.swift`) so none of them are wrong after the split
  (rule: a stale instruction is worse than a missing one).
- Tests added: `StoreMigrationTests.swift` (5 cases — the real migration, a purge-pending marker
  carried over, idempotency, a fresh install, and the "App Group never configured" no-op), plus
  `SnapshotStoreTests.swift` (`sharedRootPutsOnlyTheGlanceInTheAppGroupDirectory`,
  `aWidgetStyleReaderOverOnlyTheSharedRootReadsTheGlance`) and `AccountPurgerTests.swift`
  (`purgeRemovesBothDirectoriesWhenTheGlanceIsSplitOut`).

## SEC1-05: per-institution OAuth redirect (mix-up defence)

- Read `Authorization.swift`, `TokenEndpoint.swift`, `WebAuthPresenter.swift`,
  `SignInHandoffViewModel.swift`, `ClientRegistry.swift`, `InstitutionHost.swift`,
  `InstitutionRegistry.swift`, `WelcomeFlowView.swift`, `security.md` §3.2 items 3-4 and §4's
  threat table (lines 76, 81, 147-148), `docs/GO-LIVE.md` GL-02, the AASA file and `site/`, and
  the AppIdentifier entitlements. Key finding: `OAuthCallback.code(from:for:now:)`
  (`Authorization.swift:54-58`) already requires the callback's path to equal
  `request.redirectURI.path` **exactly** — the mix-up defence RFC 9700 §4.4.2 asks for (a
  distinct redirect per authorization server) was already structurally enforced by that
  comparison; the only missing piece was ever constructing a *distinct* redirect per
  institution in the first place (`SignInHandoffViewModel.defaultRedirectURI` was one fixed URL
  for every school).
- Added `InstitutionID.derive(host:)` (new file, `TallyCanvasAPI/Auth/InstitutionID.swift`): a
  truncated hex SHA-256 of the institution's Canvas host (`TallyConfig.institutionIdHexLength`,
  new config constant, `AuthConfig.swift`, mirroring `StoreConfig.swift`'s own pattern for
  `accountKeyHexLength`) — deterministic and opaque, so the school's domain never appears in a
  URL path (the same reasoning `AccountKey.derive` already applies to notification IDs).
- `SignInHandoffViewModel.redirectURI(forHost:)` replaces `defaultRedirectURI` at its one
  production call site (`WelcomeFlowView.swift:78`, where `host` was already in scope):
  `https://<TallyOrgDomain>/oauth/callback/<institutionId>`. `defaultRedirectURI` itself stays
  (now internal, still covered by its own pre-existing test) only as the unreachable-fallback
  value and so a key an admin already registered against the old fixed path still has somewhere
  to land — never breaking the registered callback, since nothing institution-specific changed
  about the domain, the entitlement or the fallback page.
- **Verified, not assumed, that no AASA or entitlement change is needed**: `WebAuthPresenter.swift`
  passes `.https(host: callbackHost, path: callbackPath)` with both values threaded through
  dynamically from whatever `redirectURI` the view model built — Apple's documented contract for
  `ASWebAuthenticationSession.Callback.https(host:path:)` needs only the domain's `webcredentials`
  association (security.md's own citation table, line 407, already marks this VERIFIED), no `paths`
  list. The report's Fix note suggested an AASA change; I found, by reading the actual code and
  Apple's contract, that it isn't required, and recorded why rather than making an unjustified
  change to a security-sensitive file (rule 8).
- **Site**: added `site/404.html`, byte-identical to the existing `site/oauth/callback/index.html`
  (no new copy) — GitHub Pages serves it for any path with no directory of its own, so a
  per-institution path hit directly in a browser (the same residual SEC1-17 already accepts for
  the single old path) gets the same neutral landing page instead of a bare 404.
- `docs/GO-LIVE.md` GL-02 (a living checklist, not a frozen review): its one line describing the
  site layout said "AASA with webcredentials + applinks for /oauth/callback" — `applinks` was
  never actually wired (SEC1-17's own accepted residual), and the path is no longer static. Updated
  that line, in place, to the real path shape and why `applinks` was never needed, so a future GL-02
  implementer doesn't configure an AASA entry for the wrong, pre-SEC1-05 path.
- Tests added (Linux, run via `make core-test`/`core-tsan` above — the 208-test TallyCanvasAPITests
  count includes all four): `institutionIDIsStableAndDistinct`, `institutionIDIsCaseInsensitive`,
  `institutionIDIsOpaque`, and the mix-up scenario itself,
  `aCallbackPathFromOneInstitutionNeverValidatesAgainstAnothers` — two institutions' requests,
  Riverside's real callback forged with Northfield's `state`, rejected `.wrongRedirect` against
  Northfield's pending request even though `state` alone would have matched. Also added
  `perInstitutionRedirectURI` to `SignInHandoffViewModelTests.swift` (Darwin-only, UNVERIFIED on
  this host; covered by the CI dispatch below).
