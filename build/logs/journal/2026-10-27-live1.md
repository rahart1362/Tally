## Verified against live Canvas (`scripts/dev/live-canvas-tests.sh`)

- First real run crashed: `CanvasClient.swift:72` (`components.url!`) trapped, because this
  harness's `host` carried `"127.0.0.1:8790"` (port folded into the host string).
  `CanvasClient.url(path:query:)` never sets `components.port` at all -- finding F3. Fixed by
  keeping `host` bare in `LiveCanvasEnvironment.Config` and restoring both the scheme (finding
  F2: `CanvasClient` hardcodes `https`) and the port in `LiveURLSessionTransport` itself, not in
  product code.
- Second run: `.authExpired` on every request -- the two tokens (minted earlier this session)
  had crossed their 120-minute TTL (RUNBOOK.md finding 2). Refreshed both with
  `~/canvas-e2e/tools/e2e_oauth.py --persona student` / `--persona observer` (the brief's own
  documented refresh step), then re-ran.
- Third run: 3 of 5 tests passed; 2 failed on count mismatches (groups: 24 vs. an assumed 19;
  events: 99 vs. an assumed 10). Investigated both read-only against the live server (see the
  report, finding F4) before touching the test: the fixture's own 19 groups (3+4+4+4+4,
  `fixtures/canvas/personas/flagship/assignment_groups/*.json`) matches "content" groups, but
  Canvas auto-creates one empty, 0%-weight "Assignments" group per course that seed.py never
  reuses (5 more); and seed.py's "10 events" are 10 rrule *series* (seed.py:522-548's own
  comment), each expanded by Canvas into many occurrences across Tally's 74-day window.  Neither
  is a Tally defect. Corrected the test's own `SeedCounts` (24 groups, exact; events as a `>=
  10` lower bound with the real count printed, not pinned, since it is date-window-dependent).
- Fourth run: 4 of 5 tests passed; the observer grade table printed `canvas=nil` for every
  course (while Tally's own `GradeEngine` computed the right score independently). Investigated
  read-only: the observer's own `GET /api/v1/courses` returns only its own `type: observer`
  enrollment row on this Canvas version -- no `student` row at all -- contradicting
  `ObserverAssignmentGroupDTO.swift`'s doc comment (based on a recorded fixture) and
  `ObserverMappingTests.courseMapperAlreadyHandlesTheObserverCoursesResponse`. Confirmed
  read-only that adding `include[]=observed_users` makes Canvas include the observee's `student`
  row (with `computed_current_score`) too -- recorded as finding F5, with a proposed fix
  (`CanvasQuery.courses()` needs an observer variant), and added the one include item to this
  test's own query (not to product code) so assertion 4 still runs end to end against a real
  response.
- Fifth run: all 5 tests, 4 suites, PASS. Full real evidence (grade tables, LIVE-PERF lines) in
  `docs/pmo/reviews/live1-report.md`.
