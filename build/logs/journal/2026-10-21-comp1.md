- `scripts/ci/check_storekit_products.py`: the hard-coded `P1M` check and its message → `P2W`/

  (`SubscriptionOfferText.trial`) and the new renewal lines (EB-18, below) all derive the length

  every one of them says. No new key was needed for EB-19 itself.

  `SubscriptionTestHooks.HookStorefront` (the UI-test stand-in), `SubscriptionStorefrontStoreKitTests`
  (the real StoreKit Testing check), `SubscriptionPlacementTests` (`SubscriptionTestOffers.annual`
  and every assertion against it), `PaywallUITests` (`assertPaywall`'s literal trial text).
- Owner action recorded for the report: App Store Connect's own introductory-offer length must
  be set to 2 weeks at submission; this PR only changes the code path and the local StoreKit
  Testing configuration.

  English value in place — the rule and the brief are explicit) and added two new keys:
  `subscription.paywall.renewalAutoCancel(price:)` and
  `subscription.paywall.trialEndsThenCharged(date:then:)`. Catalog and fixture updated to match

## EB-21 (retainable purchase confirmation)

- New file `PurchaseConfirmationView.swift`: `PurchaseConfirmationModel` (reads the plan, the
  App Store's own offer for the amount, and the current entitlement's renewal date — nothing
  persisted, so nothing can go stale) and `PurchaseConfirmationView` (a sheet reusing the EB-18
  renewal sentence for "how to cancel").
- The one-shot "just bought" signal lives on the single shared `SubscriptionModel` instance
  (`justPurchased`/`recordDirectPurchase()`/`acknowledgeDirectPurchase()`), not on `PaywallModel`
  (which is reconstructed at every presentation): `PaywallModel.purchase()` sets it only when the
  outcome is `.purchased` (never a restore, a redeemed code, a cancellation or Ask to Buy pending
  — covered by `paywallPurchase()`'s and `restore()`'s new assertions).
- Both paywall presenters already had a documented "one sheet only" lesson (run 36976774341:
  two independent `.sheet` modifiers on one view closed each other). Extended that same fix
  rather than adding a second sheet:
  - `HomeShellView`: `HomeSheet` gets a third case, `.purchaseConfirmation`; `presentedSheet`'s
    getter falls through to it once `isSettingsPresented` and `appModel.paywall` are both clear
    and `subscription.justPurchased` is true; its setter calls `acknowledgeDirectPurchase()` in
    that branch.
  - `SubscriptionSettingsView`: replaced the local `@State paywall: PaywallRequest?` with a small
    `SubscriptionSettingsSheet` enum (`.paywall`/`.confirmation`) and the same get/set pattern.
- Re-findable: Settings → Subscription's first section now offers "View Purchase Confirmation"
  whenever there is an active entitlement that is not a school-assigned seat (mirrors the
  existing `!isSchoolSeat` gate around Manage Subscription/Request a Refund).
- Tests: `SubscriptionPlacementTests.purchaseConfirmation()` (the model's four facts, read fresh
  after `.load()`); `justPurchased`/`acknowledgeDirectPurchase()` assertions folded into the
  existing `paywallPurchase()` and `restore()` tests (one guard added per outcome, matching the
  file's own style rather than duplicating the whole purchase flow in a new test). UI:
  `PaywallUITests.testSampleModeSettingsInterstitialPaywallAndPurchase` now asserts the
  confirmation appears once after the purchase, dismisses, and is re-findable from Settings →
  Subscription afterwards.
- Not implemented (open item): the backlog's longer write-up also mentions a Share button and
  capturing Apple's own purchase-sheet/receipt text for counsel's evidence file; the brief's own
  item list for EB-21 names only plan/amount/renewal date/cancel-how, shown once and
  re-findable, which is what shipped. Flagging rather than guessing scope.
