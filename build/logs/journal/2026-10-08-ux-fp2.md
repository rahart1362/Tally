## Design (one shared rule, `TallyDesignSystem/AccessibilityReflow.swift`)

- `TallyReflowStack`: `HStack` below AX1, leading `VStack(spacing: TallySpacing.xs)` from AX1 up,
  via `AnyLayout`. `TallyReflowSpacer` (the row's `Spacer`, only while side by side, so the std
  layout is unchanged byte for byte) and `TallyReflowValueColumn` (trailing beside, leading under).
- `tallyReflowValue()`: `.lineLimit(1)` + `.minimumScaleFactor(0.6)` + `.layoutPriority(1)`. Chose
  the scale factor over `.fixedSize()`: a long real-world course code ("BIOL 1010-003") at AX5 is
  wider than the smallest iPhone's row, and `.fixedSize()` would push it off the edge.
- `tallyPinnedChromeTextSize()`: pinned chrome capped at `.accessibility2`.
- `tallyCenteredScrolling()`: `ScrollView { ZStack { Color.clear.containerRelativeFrame(.vertical); content } }`
  — `containerRelativeFrame` alone fixes the height (centres, never scrolls); the ZStack is as tall
  as the taller of the two, so it centres when it fits and scrolls when it does not.
- `TallyCompactLabelStyle` (`.tallyCompact`): icon and title in an `HStack(spacing: xs)`.
- `TallyBottomBarFade`: the D03 fade (ux-fp1 round 3) as a shared view.

### Decisions worth recording

- **D04: capped pinned banner, not `lineLimit(3)`, not moved into the scroll content.** At AX5 a
  3-line cap drops the date the banner exists to show ("…showing saved data from…"). Moving it into
  each tab's scroll content changes PAY-07 ("above the signed-in Home's tabs") and, uncapped, it
  would still be ≈45 % of the smallest iPhone at the top of the scroll. Capped at AX2 with See
  Plans under the words: ≈4 lines × 32 pt + 44 pt ≈ 184 pt of 844 pt (≈22 %), every word shown, the
  time no longer split ("4:33 P / M": the column was narrower than the token).
- **D05: the actions stay pinned.** perf-app-runtime.md §7 step 3 requires both CTAs hittable right
  after launch at AX XXXL on the smallest iPhone (`WelcomeCTAUITests`, and CI's "Welcome CTAs on
  the smallest iPhone" step), so "unpin at AX sizes" would break a standing requirement. Capped at
  AX2: one line (≈68 pt) + two lines (≈108 pt) + padding ≈ 208 pt + the 34 pt home-indicator inset
  ≈ 29 % of the smallest iPhone, against ≈50 %. Plus the D03 fade above the bar, scaled with `body`
  (≈75 pt at AX5), extra bottom padding of the same height so the disclaimer clears it, and
  `.scrollIndicatorsFlash(onAppear:)`.
- **The What-If summary is capped too.** D02's stacked layout adds a line to a band pinned above
  the rows; capped at AX2 it is shorter than before, not taller.
- **The size proof in `testBothCTAsAreHittableAtAccessibilityXXXL` moves to a benefit row.** The
  capped CTA is ≈1.4× its default height (AX5 evidence: 2 lines = 155.3 pt = 2 × 63.6 + 28.1, so
  28 pt of padding; AX2: 39.4 + 28 ≈ 67 pt against 48–52 pt), too close to the test's 1.3 to prove
  the launch argument took effect. "See where you stand" is scrolling text, never capped (20.3 pt
  → 125.3 pt in the audit's own layout files).
- **D18:** `ScrollViewReader` with a strip-only id type (`WeekStripColumn`), so the agenda's own
  `scrollTo(date)` (the outer reader, by bare `Date`) can never target the strip.
- **D19:** at AX sizes the x-axis keeps its grid lines, no labels; one caption under the chart,
  `Text(start..<end, format: .interval.month(.abbreviated).day())` (locale from the environment, no
  new string key).
- **Copy:** no new or changed string. The "· " separator before the due date and the place is
  dropped only where the reflow stacks them (it would lead a line of its own); the existing key is
  unchanged.
