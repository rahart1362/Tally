## What was built

1. **Schema v7** (`UserState.swift`): `courseGoals: [CanvasID<Course>: Double]`, empty on
   migration. Migration test `migratesV6PayloadAddingNoCourseGoals` and round-trip test
   `courseGoalsRoundTrip` in `UserStateStoreTests.swift`.
   - Found and fixed a latent bug while adding this: `migratesV5PayloadAddingNoQuietHoursOverrideAndNoAdHocReminders`
     hard-coded `UserState.currentSchemaVersion == 6`; it would have failed the moment this PR
     bumped the constant to 7. Fixed to compare against the constant itself.
2. **Wiring** (display, idea 2's "the course shows its goal status"): `courseGoals` threaded
   through `ScreenLocalState`/`AccountLocalScreenStateStore` (mirrors `gradeAvailabilityOverrides`
   exactly, including sealing in `UserState` v7), `HomeProjector.setCourseGoals`/`courseGoals`
   (mirrors `setGradeAvailabilityOverrides`), `HomeModel.courseGoal(for:)`/`setCourseGoal(_:for:)`
   (mirrors `gradeAvailabilityOverride`/`setGradeAvailabilityOverride`), and `ScreenProjections.build`
   → `CourseCardBuilder.cards`, `CourseDetailBuilder.details`, `InsightsBuilder.projection` →
   `CourseHealthRules.evaluate(goal:)`. These are exactly "the three call sites" the report's own
   "what exists today" bullets name for Idea 2 (`CourseHealth`, and `WhatIfModel` below);
   `AlertEngine.belowGoalAlert` is the one call site intentionally not wired — see above.
3. **Course Detail's "Set a goal" entry** (`CourseDetailView.swift`, new `CourseGoalSection`):
   a `Stepper` (the same 50...100/step 1 pattern `WhatIfGoalSection`'s own goal stepper already
   uses) plus "Remove goal", replacing a "Set a goal" button; persists on every change, the same
   idiom `GradeOverrideMenu`'s picker already uses.
4. **Idea 6**: `WhatIfSheet`/`WhatIfGoalSection` gained an optional `onSaveGoal: ((Double) -> Void)?`
   (default `nil`, so the two existing accessibility-tree tests in `GradeControlsViewTests.swift`
   and any preview are unaffected); `CourseDetailView` wires it to the same `setCourseGoal` the
   Overview section uses. Nothing else about What-If's session-only scores changed.
5. **Sign Out & Erase**: verified, no code change needed — `AccountPurger.purge` deletes the whole
   account directory (`StoreLayout.accountDirectory`), which is where every `StoreFile` including
   `.userState` lives, so `courseGoals` goes with it structurally, same as every other `UserState`
   field.
