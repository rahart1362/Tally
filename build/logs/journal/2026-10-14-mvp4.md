**Item 1, O6 — `ReviewPathUITests.swift` (new).** Welcome → "Explore with Sample Data" (a root
switch, never a push) → Dashboard, Courses, Course detail with What-If, To-Do with Mark Done,
Calendar, Insights → Settings (About, Subscription/paywall display, parent mode) → the Sample Data
family. Two leaf classes share one walk method (`ReviewPathUITestsBase.runReviewPathWalk`):
`ReviewPathUITests` (English, full walk incl. the paywall) and `ReviewPathSpanishUITests` (es,
skips the paywall step — the Subscription interstitial is a plain `.alert` with no accessibility
identifier in either language, so it stays English-only via `PaywallUITests`' own helpers; every
other lookup here is an identifier, never an English label, except the tab bar itself, which has no
identifier to XCUITest at all — `AuditTourUITests`' own documented finding, mirrored here).

- **No network, dynamically proven.** Added `LaunchTestHooks.Key.trapAllNetwork` (new hook,
  `packages/TallyAppleKit/Sources/TallyFeatures/Launch/LaunchTestHooks.swift`): replaces
  `AccountEnvironment.transport` and `SignInServices.{institutionSearch,makeTokenExchange}` with a
  new `TrapTransport` (records into the existing `LaunchProbe` counter, then fails — never
  fabricates a response). `blockNetwork` (existing) only swaps one signed-in account's gateway,
  which Sample Data never builds, so it would prove nothing for this path. The count is exposed
  through the existing `testHook.networkProbe` identifier (`LaunchTestHookViews.swift`, now shown
  whenever `trapAllNetwork` is on too), the same one `LaunchRefreshThrottleUITests` already reads.
  Sample Data's own data path (`SampleDataCanvasGateway`) has no `HTTPTransport` dependency in its
  own init at all — it replays bundled fixtures — so the trap is defence in depth for every OTHER
  seam, not proof of sample mode's own path (that's a static fact, cited in the test's doc comment,
  not something a dynamic hook could prove either way).
- **No sign-in.** Welcome's "Explore with Sample Data" is asserted to vanish from the hierarchy
  right after the tap (a root switch would remove it; a push would not), and a sign-in attempt is
  itself a network request, so the same network-trap assertion doubles as proof no sign-in fired.
- UI-test-side launch-argument constant: `TestHooks.trapAllNetwork`
  (`apps/TallyiOS/TallyUITests/LifecycleUITestSupport.swift`).
