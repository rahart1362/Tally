**Platform facts, read from Apple's documentation JSON** (`developer.apple.com/tutorials/data/documentation/…`,
saved under `.build-m3d/apple-docs/`) unless marked otherwise:

1. *Adding interactivity to widgets and Live Activities* (sha256 `deff1f94…`): "By default, the system runs the
   app intent in the same process as the widget extension. However, if the app intent's `openAppWhenRun`
   property is `true`, or if the intent conforms to `AudioPlaybackIntent`, `ForegroundContinuableIntent`,
   `LiveActivityIntent`, or `PushToTalkTransmissionIntent`, the system performs the app intent in the app's
   process." Also: on a locked device, buttons and toggles are inactive until the person unlocks.
2. `LiveActivityIntent`: "the system launches your app process without opening the app, performs the intent…
   people might place a control in Control Center that performs a `LiveActivityIntent`".
3. *Creating controls to perform actions across the system*: control buttons run an `AppIntent` or an
   `OpenIntent`; "The system requires the Target Membership of the app intent to be set to both the app and the
   widget extension to open the app."
4. `ForegroundContinuableIntent` is deprecated in iOS 26 ("include `.foreground(.dynamic)` in the
   `supportedModes`").
5. `Widget`, `WidgetBundle`, `WidgetConfiguration` and `ControlWidget` are **SwiftUI** types (their doc pages
   live under `swiftui/`; `widgetkit/widget` and `widgetkit/widgetbundle` are 404). This explains the failure
   that made M2 collapse the widget target to one file (run 36328840843, `TallyWidgetsBundle.swift`: "cannot
   find type 'Widget' in scope"): that file imported WidgetKit only, not SwiftUI (`git show c47fad1`). The "one
   file" rule rests on a wrong diagnosis; a second file that imports SwiftUI is fine.
6. `EnvironmentValues.widgetRenderingMode` is `{ get set }` (settable, so tests can render each mode);
   `widgetFamily` is `{ get }` only (views must take the family as an input to be testable). In the accented
   mode "the system treats the widget's views as if they were template images… based on the view's alpha
   channel": colour carries no meaning there.
7. WWDC25 session 275 (transcript): "you can now put your App Intents in Swift Packages… and static
   libraries"; session 244: "an intent's title must be constant. Calling out to a function or computed
   property will result in an error." So intent titles cannot be `L10n.*()` calls.
8. Apple DTS (forum thread 770279): "App Shortcuts need to be in your main app target", phrases in
   `AppShortcuts.xcstrings`, other intent strings in a strings table of that target. DTS (thread 760806): a
   semantic-key literal title (`static var title: LocalizedStringResource = "AppIntents.UpdateText.Title"`)
   localizes from the target's table. Secondary sources (thread 732215; sowenjub.me) report that
   `LocalizedStringResource("key", table: "AppIntents")` in the declaration works for titles and parameters.
   UNVERIFIED by me until CI builds it.
9. WWDC22 session 10121 (Focus filters): "If the filter criteria on the notification does not match the filter
   predicate, the notification is silenced"; `perform()` runs in the app if it is running, otherwise only in an
   App Intents extension.

**Gate facts read from the code:**
- `check_string_catalogs.py` allows keyed lookups (`LocalizedStringResource("k", defaultValue:)`) only in
  `TallyStrings` and `apps/TallyiOS/TallyWidgets`; a plain semantic-key literal (no spaces) is neither a literal
  finding nor a keyed lookup.
- `check_privacy_manifest.py:590` requires every `project.yml` target source to be a **directory**, so code
  shared by the app and the widget must sit in its own subdirectory (`TallyWidgets/Shared/`).
- `check_widget_isolation.py` scans `apps/TallyiOS/TallyWidgets` (subdirectories included) and `TallyGlance`.

**Design decisions:**
- Intent *declarations* live in targets, not packages: app-only intents and the App Shortcuts provider in
  `apps/TallyiOS/Tally/Intents/`; the two control intents in `apps/TallyiOS/TallyWidgets/Shared/` (compiled
  into both, per fact 3); the widget configuration intent in the widget target. Their metadata strings are
  semantic keys in a shared `AppIntents` table (`Shared/AppIntents.xcstrings`, in both bundles). Logic stays in
  `TallyGlance` (glance-derived answers, the refresh answer) and `TallyIntents` (focus criteria), both mine.
- The old `RefreshTallyIntent`/`TallyShortcuts` in the `TallyIntents` package move out (an identically named
  intent type in two modules of one app would collide).
- **Interactive Done: STOPPED, options for the PMO.** It *can* be built without weakening isolation
  (fact 1: a `LiveActivityIntent` runs in the app, so the widget never writes and never holds a key), but every
  remaining part is outside this lane: the app-side handler that writes `UserState.doneAssignments` needs
  `AccountUserStateAccess` (`TallyFeatures/Settings`), a launch-time registration in the composition root
  (`TallyApp.swift`, M3-B1's; on a background launch `AppModel.attach` never runs, so the existing bridge is
  `nil`), and the glance carries no done marks, so the widget would still list the item after the tap
  (`GlanceProjection.swift`, M3-B1's). The "Due soon" widget ships without the button, with its row layout
  ready for it.
- **Focus filter:** declared in the app with Courses and only-urgent parameters (the spec's hide-names
  parameter waits for the notification scheduler, like the predicate's effect). Its notification
  predicate lets through any notification with no `filterCriteria` (today: all of Tally's), because a predicate
  that does not match silences (fact 9). Setting `filterCriteria` on notifications is the notification
  owner's follow-up; the vocabulary lives in `TallyIntents` for them.
- FAM-11: every widget uses `AppIntentConfiguration` with one configuration intent that has no parameters
  today; M3-E2 adds an optional `student` parameter to it (same kinds, placed widgets decode it as `nil`). Every
  glance read goes through one scope seam.
- Subscription: `GlanceAccess.isUnlocked(_:at:)` returns `true` until M3-B1's entitlement field merges.
