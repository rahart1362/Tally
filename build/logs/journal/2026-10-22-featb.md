## Step 2 — FEAT-5, "Add this week to Calendar" (commit `0c44373`)

Extended `DashboardProjection.WeekDay` with `items: [WeekDayItem]` (title, course code, due date,
Canvas's own link — no grade field, ever) and threaded `coursesByID` into the `weekAhead` builder,
avoiding a force-unwrap by pairing each `PlannerItem` with its already-proven-non-nil due date
before any later `.map`. Verified locally: `make core-build`/`core-test` green, 204 tests (+1 new
case, `weekAheadItemsMatchDueCounts`), no regressions to the existing parity/duplicate-ID suites
(`DashboardProjectionParityTests`, `DuplicateIDConsumerTests` — neither constructs `WeekDay`
directly, both only read `dueCount`/`isBusy`, so the new defaulted field changed nothing there).

Added `WeekAheadCalendarDraft` (pure) in `TallyFeatures/Dashboard/` and wired a new button into
`DashboardView`'s `WeekAheadSection`, walking a `[CalendarEventDraft]` queue through the existing
`AddToCalendarView` sheet one at a time — cancelling one item still advances to the next (a
deliberate choice: a bulk walk that stopped dead on the first skip would defeat the point). One
new string (`dashboard.weekAhead.addButton`).

## Step 3 — FEAT-6, "Send my week" (commit `1b750b5`)

Added `WeekShareText` (pure), reusing FEAT-5's own `WeekDayItem` list as its one data source, and
a `ShareLink` beside the "Add This Week" button. Content rules mirror `NotificationContent`'s own
R10 pattern: never a grade value (structurally — `WeekDayItem` has no such field), and "Hide
Course Names" on hides both the title and the course code, never just one. Four new strings.

## Step 4 — FEAT-8, "Open Canvas links in: App / Browser" (commit `57439fe`)

Added `CanvasLinkPreference`/`CanvasLinkPreferenceStoring` (mirrors
`NotEnabledSchoolPreferenceStoring`'s shape exactly) and refactored `CanvasLinkOpener.open` to
separate the pure destination choice (`destinations(for:preference:)`, now unit-testable without
touching `UIApplication`) from the actual `UIApplication.shared.open` loop. `isSafe` still runs
first in every mode (SEC1-15 unaffected). Added `StoreLocation.privateRoot()` (new) and
`FileCanvasLinkPreferenceStore`, and threaded the store through `AccountEnvironment` ->
`AppModel` -> `HomeModel` (both `makeSignedInHome` and `enterSample()`, so Settings and the two
"Open in Canvas" call sites — `ToDoScreen`, `CourseDetailView` — read and write one store) ->
Settings' new picker. Cleared on Sign Out & Erase (`AppModel.clearCanvasLinkPreference()`,
mirroring `clearNotEnabledSchool()`). `AccountLifecycleTestSupport.swift`'s harness gained one
new, defaulted, additive field (`canvasLinkPreferences`) — every existing call site compiles
unchanged. Three new strings.
