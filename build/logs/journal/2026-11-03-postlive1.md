## Item 3: RemindersTests.swift test flake

- Confirmed the PMO's diagnosis against the code (not taken on faith) before fixing:
  `ReminderRig.coordinator()` (`RemindersTests.swift`) calls
  `FlagshipAccountGateway.flagship(account:)` with no `now:`, and that static func
  (`AccountLifecycleTestSupport.swift`) hard-codes `FlagshipSnapshotHarness.fetchSnapshot(now:
  Date())` -- a second, independent real-clock read, never the rig's own fixed `now`. Traced the
  wording to `ReminderPipeline.run` (`packages/TallyAppleKit/.../ReminderPipeline.swift:170-171`):
  `refresh.succeeded(dataFetchedAt: snapshot.fetchedAt)`, then `lastSuccess: refresh.lastSuccessAt`
  feeds the sentinel reminder's rendered body ("Tally hasn't refreshed since yesterday at H:MM").
  Two `ReminderRig()`s built back-to-back in
  `defaultLocaleMatchesTallyLocaleEffective` each took that real-clock read at a slightly
  different instant; across a minute boundary the formatted H:MM differs, so
  `defaultWords != explicitWords` -- exactly main's iOS ASan run 40685358106.
- Fix (test-only, no product code touched): added an optional `now:` parameter (default `Date()`,
  so every other existing call site is byte-for-byte unchanged) to
  `FlagshipAccountGateway.flagship(account:generation:now:)`, and `ReminderRig.coordinator()` now
  passes its own fixed `now` through. Both rigs in the flaky test default to the same
  `ReminderTestSupport.anchor`, so their snapshots' `fetchedAt` -- and so the sentinel's wording --
  are now identical by construction, not by luck.
- Looked for the same two-rigs pattern elsewhere in `TallyAppTests`: the only other
  `.flagship(account:)` call sites compare counts/structure, never time-formatted text, and
  `FreshnessPresenterTests.defaultLocaleMatchesTallyLocaleEffective` (cited by this test's own
  comment) already uses fully fixed `Date(timeIntervalSince1970:...)` values throughout -- no

  test-support) to add `close()` for protocol conformance; neither is production code.
