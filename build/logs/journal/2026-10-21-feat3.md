## Design decisions

- **Idea 4 persistence.** The ad-hoc request is **not** scheduled directly against the platform;
  it is written to a new `UserState.adHocReminders: [CanvasID<Assignment>: Date]` field and the
  existing reminders pass (`ReminderPipeline.run`) plans it through `ReminderPlanner.plan`'s new
  `adHocReminders` parameter. This was the only design that survives the pipeline's own periodic
  reconcile: `NotificationReconciler.reconcile` cancels anything pending that the *next* pass does
  not re-desire, so an ad-hoc reminder scheduled only once, outside the planner, would be cancelled
  by the very next commit's pass. Routing it through `UserState` means every later pass keeps
  planning it — and "cancelled when the item is marked done" falls out for free: `ReminderSubjects`
  already excludes a done assignment from the candidates the planner ever sees
  (`PriorityScore.isExcluded`), so the next pass (already triggered automatically on a done-mark
  change, `AccountLocalScreenStateStore.onDoneMarksChanged`) simply stops desiring it.
- **Idea 5 wiring.** `ReminderPipeline.run` reads `state.quietHoursOverride` alongside
  `hideCourseNamesInNotifications` in the same read-only switch, and passes
  `quietHoursOverride ?? QuietHours()` into `ReminderSettings(quietHours:)` — the planner's
  existing parameter, unused by any caller before this change. Settings' two `DatePicker`s write it
  back through the same `SettingsModel.save`/`notificationSettingsSaved` pattern
  "Hide Course Names" already uses, so a change re-plans at once.
- **Schema.** `UserState` v5 → v6 in one bump, both ideas' new fields together (`quietHoursOverride: QuietHours?`,
  `adHocReminders: [CanvasID<Assignment>: Date]`), per the brief: "FEAT-4 also bumps `UserState`
  next. Keep the migration minimal and well tested." `QuietHours` gained `Codable` (it was
  `Sendable, Equatable` only).
- **Exhaustive switches.** Adding `NotificationKind.adHoc` and `NotificationMessage.adHocReminder`
  required updating three other exhaustive switches that do not take a `default:` case:
  `UNNotificationScheduler.ReminderContent.generic(for:)` (2 new generic strings,
  `notifications.generic.adHoc.*`), `ReminderSubjects.message(for:)`, and the frozen
  `LegacyEnglish628ee09.swift` oracle (a minimal branch reusing `Notification.examReminder`'s exact
  shape — there is no 628ee09 text to pin for a case that never existed then).
