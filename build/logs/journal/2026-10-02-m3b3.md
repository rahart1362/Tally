## 2. Engine → model: carrying `holding`

- `SubscriptionStatus` gained `holding: SubscriptionHolding?`. `SubscriptionEngine.run(_:)` computes
  it from the same facts as `accountState` (`EntitlementPolicy.holding`) and passes it to `apply`;
  the launch's first, offline publish (from the Keychain record, before `source.currentFacts()`
  returns) passes `holding: nil`, since `EntitlementRecord` carries no ownership. **Decision:** did
  **not** persist holding to the Keychain record — it is not trivially additive (the record's schema,
  `recording(_:for:verifiedAt:)` and every persisted-record test would need a new field for a value
  that is only ever stale between launches anyway, since StoreKit always re-verifies at launch,
  PAY-04), so a nil-until-known model was the right size for this package.
- `SubscriptionModel` mirrors `holding` from `SubscriptionStatus` in `receive(_:)` and adds
  `isSchoolSeat` (`holding == .schoolSeat`; `false`, i.e. today's purchase UI, while unknown).
- `SubscriptionStatusText.status` takes an optional `holding` (default `nil`) and returns the new
  school-seat status text only for `.schoolSeat`; `nil` and `.purchase` both read as "Active until
  %@", exactly today's text, so the uncertain window never shows a seat.
