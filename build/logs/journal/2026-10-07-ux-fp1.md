## D01 (S1) — content under bar titles

`TallyScreenChrome` (`ScreenChrome.swift`): `.scrollEdgeEffectStyle(.hard, for: .top)` (iOS 26).
Chosen over `.toolbarBackground(...) + .toolbarBackgroundVisibility(.visible, ...)` because it is
the API iOS 26 itself exposes for this exact problem (how much the scroll-edge effect occludes vs.
fades content) without swapping the bar's own Liquid Glass material for a flat fill — the
acceptance criterion says "the bar still reads as native iOS 26." Applied via `tallyScreenChrome()`
to: `DashboardView`, `InsightsScreen` (ScrollView); `CoursesScreen`, `ToDoScreen` (select mode
included — same List), `CalendarScreen`, `CourseDetailView`, `WhatIfSheet` (List); `SettingsView`,
`PerCourseThresholdsView`, `WhatTallyStoresView`, `SubscriptionSettingsView`, `PaywallView`,
`StudentDetailView`, `AddStudentSheet`, `ObserverDetailView`, `HowToRemoveSheet`, `InviteSheet`
(every Settings/Subscription/Family Form and the Paywall sheet, per D01's acceptance list).

Not applied to `SchoolSearchView` (onboarding, not in D01's named screen list) or to Lock.

## D27 (S3) + D31 (S2, dark) — List edges and the two dark palettes

One `tallyList()` modifier (same file): `.contentMargins(.horizontal, TallySpacing.screenMargin,
for: .scrollContent)` + `.scrollContentBackground(.hidden)` + `.background(TallyColor.bgCanvas)` +

What-If's own dark fix (named directly in D31's text, not just the apply-list): the sticky summary

## D03 (S1) + D22 (S3) — destructive confirmations

Grepped every `.confirmationDialog` in `TallyFeatures`: exactly 3, exactly the three D03 names
(`SettingsView.swift:98` sign-out, `FamilySettingsViews.swift:125,132` remove/unlink) — the audit's

## D29 (S2, dark; safe-area part only) — sample banner under the status bar

`SampleDataBanner.swift`: `.background(TallyColor.accent)` → `.background(TallyColor.accent,
ignoresSafeAreaEdges: [])`. SwiftUI's `View.background(_:ignoresSafeAreaEdges:)` defaults that
parameter to `.all`, so the plain call was already bleeding the fill under the status bar — this is
why the status bar's own glyphs sat on the accent colour instead of the canvas. The glyph-contrast
half of D29 (an `accent.fill` token) is FP-6's; left untouched.

## D17 (S2) — menus truncate or overlap

Course menu: `GradeOverrideMenu`'s nested `Picker(.pickerStyle(.menu))` inside a `Menu` showed its
`label:` text as a single-line submenu row — iOS menu rows truncate, never wrap, so
"This course's grades are kept outside Canvas" clipped to "…kept outside Ca…" on the smallest
iPhone. No layout-only fix exists for a system menu row's text. Added a NEW key
(`courseDetail.override.menuRowTitle`, "Grades kept outside Canvas") used only at this row;
`courseDetail.override.title` (the full question) is untouched and still used wherever there is
room. **Pending owner approval** (recorded in the report).

Family switcher: `StudentSwitcher`'s `Menu` drew "Manage linked students…" over the Dashboard hero
at AX5 (a `Menu` cannot reflow for Dynamic Type). At `typeSize.isAccessibilitySize` the switcher is
now a `Button` that presents a sheet (`StudentSwitcherSheet`): a `List` of students with a checkmark
on the active one, then the same two actions, reusing `onManage`/`onAdd` unchanged. Below AX1 the
original `Menu` is untouched. Verified against `FamilyUITests`: the one existing AX5 test
(`testSwitcherAtAX5ShowsInitialsAndPassesTheAudit`) only reads the switcher's label/frame and runs
the accessibility audit — it never taps to open the menu, so it is unaffected; no other test opens
the switcher at AX5.

## D26 (S3) — school search bar cut by the keyboard at AX5

`SchoolSearchView.searchable(...)`: added a `placement:` that switches to
`.navigationBarDrawer(displayMode: .always)` once `typeSize.isAccessibilitySize`, so the field pins
above the keyboard instead of docking at the bottom where it was clipped. Below AX1, `.automatic`
(unchanged). The audit flagged this device check as unresolved from the simulator; this host has
none either, so the "after" audit captures are the verification, and I still record a device check
as an open item.
