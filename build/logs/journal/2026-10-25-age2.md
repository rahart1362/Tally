- **Root cause.** Every failing test (and no passing one) reaches the paywall through

  `evaluateBeforePaywall()` now gates on. None of them pass `-TallyTestHooks.ageAssurance`, so

  call was fire-and-forget, so nothing depended on it finishing. Awaiting it for the first time

  await on an Apple API, now gating the whole purchase flow. Every passing `PaywallUITests` case
  reaches the paywall through Settings → the interstitial, a path that never touches
  `AgeAssuranceModel`, which is why only these three broke.
- Stopped per the binding rule rather than iterating blindly; reported the hierarchy/assertions and
  this hypothesis. **PMO ruling:** confirmed the analysis; directed a BOUNDED wait (race the
  request against a timeout, present anyway on timeout, let the request finish in the background),
  never a `#if targetEnvironment(simulator)` special case.

## 2026-10-25 | The bounded-wait fix (PMO-directed)
- `TallyConfig.ageAssurancePaywallWaitBudget: Duration = .seconds(3)` (new named constant, with the
  other age-assurance config).
- `AgeAssuranceModel.evaluateBeforePaywall()` rewritten: (1) `isPaywallRequestDue()` first decides
  via `AgeRequestPolicy.trigger(for:)` whether anything is due, touching only the cheap stores
  (`recordStore`/`versionStore`/`ageRating`) and never `requester`; when `hasRequestedThisProcessLaunch`
  is already true (the common case) it returns `false` with zero awaits of any kind, by construction
  (`AgeRequestPolicy.trigger`'s first guard rules it out regardless of the rest of the input, so
  there's nothing to even read). (2) If something is due, races the real `evaluate()` against
  `sleepForPaywallWait(TallyConfig.ageAssurancePaywallWaitBudget)` using a `PaywallWaitGate`
  (continuation-based, same shape as `HomeModel`'s private `ResumeGate` for
  `refreshUntilSettledOrDelayed` -- not reused directly, since that one is file-private). Whichever
  side finishes first resumes; the loser (typically the hanging request) keeps running, owned by
  `evaluateTask`, until it finishes on its own or a later call supersedes it.
- The wait is injectable: `init` is now generic over `<C: Clock>` with a `paywallWaitClock: C =
  ContinuousClock()` parameter, captured as a `sleepForPaywallWait` closure (the exact shape
  `CanvasClient`'s `clock`/`sleep` parameters already use in this repo, so no new idiom). Every
  existing call site (none of which passed a clock) is unaffected: `C` infers from the default.
- `docs/release/age-assurance-device-checks.md`: corrected item 4's old assumption ("no window,
  quick `.unavailable`") to what was actually observed (the call hangs); added item 5a describing
  the bounded wait, the accepted `.unavailable`-on-collision trade-off, and what to record.
- **Tests** (`SubscriptionPlacementTests.swift`): generalized `GatedAgeAssuranceRequester` with a
  persistent `released` flag (so `unblock()` works whether called before or after the real call)
  and a `callCount`; added `GatedClock` (a `Clock` whose `sleep` suspends until the test calls
  `fire()` -- deterministic, no real waiting). Three new tests match the PMO's list exactly:
  `paywallPresentsAfterTheWaitWhenTheRequestHangs` (hanging requester + fired clock: paywall
  presents, `outcome` stays `nil`), `paywallPresentsFromAFastRequestNotTheTimeout` (released
  requester + never-fired clock: paywall presents from the request, `outcome == .unavailable`),
  `paywallPresentsAtOnceWhenNoRequestIsDue` (a forced prior request, then the paywall trigger:
  `requester.callCount` stays at 1). Kept the existing `paywallAwaitsTheAgeRequestBeforePresenting`
  (ordering, unaffected by this change).
