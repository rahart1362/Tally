## Implementation (one commit)

- **New shared component** `TF/Support/TallyOptionsSheet.swift`: a plain sheet (title, each choice
  as a full-width ≥44 pt row with an optional checkmark, then Cancel), following D03's AX1+ pattern
  (`DestructiveConfirmation.swift`) but for a selection/menu replacement rather than a destructive
  confirmation. Used by both UX2-10 call sites so they read and behave the same way.
- **UX2-10, Course Options** (`CourseDetailView.swift`, `GradeOverrideMenu`): kept the
  `confirmationDialog` below AX1 (the binding's `get`/`set` now gates on `!typeSize.
  isAccessibilitySize`, the same trick `tallyDestructiveConfirmation` uses); added a `.sheet` for
  AX1+ presenting `TallyOptionsSheet` with the same three choices, a checkmark on the current one
  (the flattened std Menu already shows one; the old confirmationDialog never did — this makes the
  two presentations consistent, not just parity), and Cancel. Reused `L10n.Settings.cancel()` (no
  new string), the same reuse the UX2-17 finding itself proposed. Accessibility identifiers
  unchanged (`courseDetail.gradesOutsideCanvas.<option>`), so `AuditTourUITests.testB2_…` and
  `AccessibilityAuditUITests.a11yReachCourseOptions` need no changes — they find the choice by id,
  never by presentation style.
- **UX2-10, Calendar options menu** (`CalendarScreen.swift`): same cut, but in the toolbar `Menu`
  itself (not a second-level dialog) — at AX5 the Picker is already hidden (`offersTimeline`
  returns false), so the Menu's only content is the "Subscribe to Canvas Calendar…" row, and that
  row is what iOS 26 cuts. At AX1+, a plain `Button` opens `TallyOptionsSheet` with the one
  Subscribe option (when `subscribeURL` exists) in place of the `Menu` outright; below AX1 the
  `Menu` is byte-identical to before (simplified the surviving `typeSize.isAccessibilitySize ||
  typeSize == .xxxLarge` check to just `typeSize == .xxxLarge`, since the AX condition can't be
  true inside that branch any more). `calendar.options` keeps its identifier on both branches, so
  `CalendarUITests`, `AuditTourUITests.testD_calendar` and
  `AccessibilityAuditUITests.navBarGlassButtonIdentifiers` are unaffected.
- **UX2-14** (`DashboardView.swift`, `WeekAheadSection`): the day-strip `HStack` and the (now)
  conditional footer are both inside one `VStack(spacing: 0)` that carries the card background
  (previously only the day strip had it); a `Divider()` plus a new `WeekAheadActionsRow` (Add This
  Week to Calendar / Send My Week, each a `Label` with `calendar.badge.plus` /
  `square.and.arrow.up`, ≥44 pt, inside a `TallyReflowStack` so they sit side by side at std and
  stack at the accessibility sizes — D02's own pattern, already used four other places in this
  file). Accessibility identifiers unchanged (`dashboard.addWeekToCalendar`, `dashboard.shareWeek`).
  Used the existing strings (`L10n.Dashboard.addWeekButton/shareWeekButton`); the `Label { Text(
  resource) } icon: { Image(systemName:) }` form matches the L10N-03a-verified-safe pattern already
  used elsewhere in this file and in `CourseDetailView.swift`, not a bare `LocalizedStringResource`
  passed to `Label(_:systemImage:)`.
- **UX2-18** (`GlanceListWidgetViews.swift` `GlanceWeekStrip` + `GlanceTimeline.swift` +
  `GlanceText.swift` + `GlanceWidgetViews.swift`): added `GlanceSummary.Day.isToday` (true for the
  week's first column — `week(of:at:calendar:cutoff:)`'s existing `offset == 0`), a
  `GlanceText.dayNumber(_:calendar:locale:)` formatter, and `GlanceMetrics.dayMarkDiameter` (16 pt,
  fixed — a widget's layout is fixed, unlike the in-app strip's `@ScaledMetric`). `GlanceWeekStrip`
  now draws the day number between the weekday and the count, ringed (`style.accent`, `AnyShapeStyle`
  — already used for `.foregroundStyle` elsewhere in this file; `Shape.strokeBorder<S: ShapeStyle>`
  accepts it the same way) when `isToday`, matching the in-app strip's letter/number/ring format
  (`WeekDayMark` in `DashboardView.swift`). `GlanceSummary.Day`'s memberwise `init` gained the new
  parameter; grepped the whole repo first and confirmed the planner's `week(...)` is its only call
  site, so this is not a source break anywhere else. Added one cheap assertion to
  `WidgetPlannerTests.swift`'s existing `weekStrip()` test (`summary.week.map(\.isToday) == [true,
  false, false, false, false, false, false]`) rather than a new test file.
