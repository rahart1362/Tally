- UX1-04/UX1-09 — `SignInHandoffView.swift`: `expectationCard`'s `VStack` to `.leading`, plus a
  full-width frame on each `ExpectationRow`; dividers now inset from a named `dividerInset`

- UX1-38/UX1-31 — `Insights/ScreenCharts.swift`: `TrendChart.chart` gets its own
  `.chartXAxis`/`.chartYAxis` (styled label colour, capped tick count via

  grid lines only, no labels) still applies afterward, unchanged.
- UX1-01 — `TallyDesignSystem/ButtonStyles.swift`: both button styles now give `configuration.label`
  a `.frame(maxWidth: .infinity)` *inside* the style (plus `.buttonSizing(.flexible)` on iOS 26+),
  so a call site's own outer `.frame(maxWidth: .infinity)` (unchanged, still present everywhere)
  actually reaches the capsule.
- UX1-11 — new `TallySpacing.tabRootMargin(containerWidth:)` + `TallyScreenWidthReader`
  (`ScreenChrome.swift`, a zero-footprint `GeometryReader` behind `Color.clear`) + an optional
  `margin:` param on `tallyList()`. Wired into exactly the four large-title tab roots
  (`DashboardView`, `CoursesScreen`, `ToDoScreen`, `InsightsScreen`) via a local `@State
  screenMargin`, each read independently — Calendar, Course detail, What-If and the student
  switcher sheet (also `tallyList()` callers) are untouched, so this cannot leak into a pushed or
  sheeted screen through the navigation/sheet environment the way a shared environment value set
  once in `HomeShellView` would have.
- UX1-05/UX1-07 — `SchoolSearchView.swift`: `.searchPresentationToolbarBehavior(.avoidHidingContent)`
  on the std `.searchable` branch; `.onChange(of: viewModel.state)` drops `searchFieldFocused` on
  `.searchFailed`/`.offline`.
- UX1-35 — new `isParentModeHome` environment value, set once in `HomeShellView` alongside
  `.environment(home)`; read only by `DashboardView.header`, so the broad cascade (unlike the
  margin above) is harmless — nothing else consumes it.
- UX1-27 — `ToDoScreen.swift`: the done circle's `.frame(width: 44, height: 44)` →
  `.frame(minWidth: 44, minHeight: 44)`.
- UX1-12 — `DashboardProjection.DueItem` gains `isToday: Bool = false` (default keeps any
  unknown caller source-compatible), computed in `dueSoon(...)` and `HomeGlance.make` with the same
  Gregorian/`.current` calendar `weekAhead` already uses. `DashboardView`'s `DueSoonSection` reads
  it to choose a bare time or `.dateTime.weekday(.abbreviated).hour().minute()` — no `Date()`/
  `Calendar.current` read inside the view (perf-app-runtime.md §3 item 4: views have no clock).
- UX1-25/UX1-28 — `TallyReflowStack` gains an additive `stacksAtXXXLarge: Bool = false` param and
  `TallyReflow.isStacked(at:stacksAtXXXLarge:)`; `ToDoScreen`'s row and `CalendarScreen`'s
  `AgendaRow` pass `true`. Deliberately did NOT introduce a new component that swaps the whole
  child-view tree at the AX1 boundary (an earlier draft did, then was reverted) — Calendar's own
  comment ("the audit loses a text that is replaced as it grows") flagged that exact risk for the
  element the Xcode accessibility audit was tracking live across a size sweep; the chosen fix only
  moves the *existing* stacked/unstacked threshold one step earlier, reusing the
  `CourseCardView.usesFullWidthColumn` precedent, so the children's identity across that boundary
  is unchanged from before this patch.
- UX1-39 — `CalendarScreen.swift`: the subscribe menu item drops its icon (`Label` → `Text`) from
  `xxxLarge` up.
- UX1-19 — `CourseDetailView.swift`'s `GradeOverrideMenu`: `isAccessibilitySize` now presents a
  `confirmationDialog` instead of the nested `Picker(.menu)`. Calendar's own options-menu instance
  of the same system-level truncation is unresolved (its menu is already flat, not nested; the
  report offered no code-level fix for that shape) — recorded as an open item.
- UX1-17/UX1-18 — `CoursesScreen.swift`'s `CourseCardView.body` split into `standardLayout`
  (top row: name/code, sparkline, grade; then a full-width `metaRow` for Next/the chip) and
