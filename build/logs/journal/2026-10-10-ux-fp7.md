## Design decisions

- **G2 first** (order of work item 1), then N1/N2/D23 — brief's own order, so the renders used to
  judge the layout fixes are already trustworthy.
- **G2 gap 1** (false bg.brand in accented/vibrant): `hostedPNG` now paints a neutral stand-in
  (`Color(white: 0.55)` light, `Color(white: 0.07)` dark) instead of `TallyColor.bgBrand` whenever
  `mode != .fullColor`, and `snapshot`'s attachment name gets a `-neutral-bg` suffix for those so a
  reviewer never reads the stand-in as the real brand colour.
- **G2 gap 2** (accessory backdrop draws nothing under `ImageRenderer`): added a visible
  `Color.black.opacity(0.55)` stand-in chip (circle for the circular accessory, rounded rect for
  the rectangular one), labelled `-standin-bg`.
- **G2 gap 3** (no hosted Mark Done render): added `dueSoonWithMarkDoneHostedSnapshot`, light and
  dark, through the same containerBackground/margin composition as `hostedPNG`.
- **G2 gap 4** (2x vs the 3x device): `hostedPNG`'s `renderer.scale` is now 3. Left the plain,
  unbacked `renderer()` (used by the functional/pixel tests — contrast, alpha, locked-rendering
  identity) at scale 2: nothing asked for those to change, and scale doesn't change what those
  assertions measure.
- **G2 gap 5** (no smallest-phone renders): added `PhoneClass` (`proMax`/`smallest`) with the
  390 pt-wide class's documented small/medium sizes (158×158, 338×158 — Apple's HIG
  "Specifications," the same source the test file's existing comment already cites for the Pro
  Max sizes) and a new `smallestPhoneSnapshot` test over the four surfaces N1/N2 are about
  (next-up-small, standing-small, standing-medium, due-soon-medium).
- **N1** (Standing small truncates "N courses not included"): copy is frozen, so this is a layout
  fix only — the caption's `lineLimit` goes from 1 to 2. The surrounding `Spacer(minLength: 0)`s
  already yield before a `Text` with room to grow does, so the extra line doesn't need any other
  change.
- **N2** (Due soon content ~12 pt taller than its box): `TallySpacing.xs` (4 pt) is already the
  smallest named token, used in every gap this layout has — there was no "tighter row spacing"
  left to take without touching a token every other screen also uses. Went with the brief's other
  example instead: `DueSoonWidgetView` now wraps its row list in `ViewThatFits(in: .vertical)`,
  trying `dueSoonRows` (3) first and falling back to `dueSoonRows - 1` (2) only when 3 doesn't fit
  the height the system actually proposes — device-size-agnostic rather than a hardcoded
  per-device row count.
- **D23** (Week ahead's two gaps, 36 pt / 88 pt, more than 2:1 apart): read the layout as nested
  `Spacer`s — one in `WeekAheadWidgetView`'s own `VStack`, the other one level down inside
  `GlanceItemList`'s `VStack` — which is why they weren't splitting the slack evenly: each VStack
  level computes its own flexible-child share independently, and `GlanceItemList`'s ideal height
  (itself unbounded because of its own internal spacer) absorbed a different proportion of the
  outer VStack's distribution pass than a plain sibling `Spacer` would. Extracted `GlanceItemRows`
  (the rows alone, no footer, no spacer) out of `GlanceItemList`, so `WeekAheadWidgetView` can
  place its two `Spacer(minLength: TallySpacing.sm)`s and the footer as direct siblings of the week
  strip and the rows, all in one `VStack` — letting SwiftUI's single-level distribution split the
  remaining space between the two (now sibling) spacers. `GlanceItemList` (Due soon) is unchanged
  from the outside: `GlanceItemRows` + its own trailing spacer + footer.

## Step 7 — N1 regression, round 2: still broken, root-caused to layout priority

Read the dispatch-2 smallest-phone renders (`pmo-audit/.build-audit/fp7/after-38048446466/
audit-proMax-light-std/widget-standing-small-full-color-{light,dark}-smallest.png`): identical
truncation to before — "Average of 2 cours…" — commit `1689063` made no visible difference there.
Wrong diagnosis the first time: pinning the first caption to `lineLimit(1)` doesn't change what it
renders when the surrounding layout only ever gave it one line's worth of *height* regardless of
its `lineLimit` value.

Measured the actual row bands with `d23_gaps.py` on both the smallest (158×158 pt) and Pro Max
(170×170 pt) renders of `widget-standing-small-full-color-light{,-smallest}.png`:
- Smallest: header 20.00 pt, gap **16.33 pt**, badge 27.67 pt, gap 6.67 pt, caption-1 (1 line)
  12.33 pt, gap 7.67 pt, caption-2 line 1 9.67 pt, gap 8.00 pt, caption-2 line 2 10.00 pt, bottom
  gap 23.67 pt.
- Pro Max: same shape, gap above the badge **20.33 pt** instead.
- The gap *above the badge* — the `Spacer(minLength: 0)` before `GradeBandBadge` — is holding
  16–20 pt it doesn't structurally need (the gaps between the caption lines, driven by font
  leading + `TallySpacing.xs`, run 6.67–8.00 pt), while the caption below is squeezed to exactly
  one line and forced to truncate. A plain `Spacer(minLength: 0)` doesn't reach its floor just
  because its minimum is lower than a `Text`'s — the VStack negotiates every default-priority
  flexible child together, and nothing here outranked the caption that actually needed the room.
- Fix (commit `f30c495`): both captions back to `lineLimit(2)` — either one can be the long one,
  not just the "not included" one — plus `.layoutPriority(1)` on both, so the two
  `Spacer(minLength: 0)`s (one above the badge, one below the captions, both default priority)
  give up their space first. Back-of-envelope check from the measured bands: the two captions'
  combined natural 2-line need is ~44 pt against the ~153 pt of non-spacer content the box already
  reliably fits (158 pt box, 16+24 pt margins) — there's room once the spacers actually compress.
- Both Audit tour dispatches are spent (budget: at most 2). `iOS build + test`'s own
  `ui-test-screenshots` artifact (confirmed present on run `38044640380`) carries the same
  `WidgetFamilyRenderTests` attachments a CI run already produces outside the Audit tour workflow,
  so CI iteration run 3 of 3 is being used to verify this against a real render instead.
- `make lint`: 0 violations after this change too.
