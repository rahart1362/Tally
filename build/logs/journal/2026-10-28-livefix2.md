## Item 5: pagination must not silently truncate

- `CanvasClient.fetchAllPages`/`fetchAllPagesOrSkip` share a new `continuePaginating` helper;

  `CanvasGateway.optionalSection`, which already carries the previous value forward flagged
  `carriedForward` -- so "the snapshot is marked incomplete" falls out of the EXISTING mechanism,

  required-section failure already does.

  live Alex gate (planner is a required section): confirmed by reproducing it with a direct curl

## Round 2 (PMO review of PR #101 @ `c38de2e`): the ETag cache was unbounded

- Verified the diagnosis against the actual code, as asked, before changing anything:
  `CanvasEndpoints.swift:108-121` confirmed -- `plannerItems`/`calendarEvents`/`announcements`
  all take `start`/`end` from `CanvasDateWindow.dateString` (`CanvasEndpoints.swift:70-84`,
  UTC-day Gregorian calendar, confirmed by reading it directly), so those three endpoints' URLs
  (and so their cache keys) change every day. `SealedETagStore.setEntry` (pre-fix) called
  `try? store.save(entries)` on every single call -- confirmed by reading the file, not assumed.
- **Erase Saved Data finding, proven before writing any fix**: `AppModel.eraseSavedData()`
  (`AppModel.swift:641-654`) calls `coordinator.eraseLocalData()` then
  `AccountSignOut.eraseSavedData` (file deletion only); `RefreshCoordinator.eraseLocalData()`
  (`RefreshCoordinator.swift:343-349`, unchanged by this fix's diagnosis step) only resets
  `committedSnapshot`/`committedGeneration`/`record` -- it never touches `self.gateway`. So the
  account's existing, live `CanvasClient`/`SealedETagStore` is never rebuilt by an erase; its own
  doc comment already states the INTENDED invariant this breaks ("the next refresh rebuilds
  exactly what `AccountSignOut.eraseSavedData` deleted on disk"). **Finding: the runtime is NOT
  rebuilt; fixed by clearing the in-memory cache on erase**, not by proving a rebuild (there
  isn't one).
- Implementation: `ETagCacheEntry.lastUsedAt` (stamped from `CanvasClient`'s own `wallClock`, on
  write and on a 304 hit); `ETagCachePruning` (pure, `TallyDomain`) drops by age then

  `SealedETagStore` takes a `clock`/`maxAge`/`maxBytes`; `ETagCacheStore.currentVersion` -> 2;
