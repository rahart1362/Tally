## 4. The fix (`c651d62`, local until round 2 is read)

- `TallyStrings/L10n+Lookup.swift` (new): `L10n.string`, five overloads, each taking the `L10n`
  function itself, so a key can never be cached with one call's arguments:
  - `() -> LocalizedStringResource`: the key's text, cached;
  - one, two or three `String` arguments: the key resolved once with private-use placeholders
    (U+E000-U+E002), then filled in one pass, so an argument holding a placeholder's code point is
    never rewritten;
  - one `Int` (a plural): the full text per number, for numbers in `L10n.cachedCounts` (0...999,
    a named constant); any other number goes to `String(localized:)` every time.
  - Cache: `Mutex<[Key: String]>` in a `final class Sendable`, keyed by bundle, table, key, locale
    identifier (and the plural's number). No `nonisolated(unsafe)`, no `Task.detached`, no
    `uniqueKeysWithValues`.
- 102 call sites converted (`.build-perf/convert.py`, which reads each `L10n` function's signature from
  the TallyStrings sources, converts no-argument, all-`String` (1-3) and single-`Int` keys, and lists
  what it skips): ScreenFormatter, ToDoProjection, CourseDetailProjection, CourseCard, CourseHealth,
  InsightsProjection, GradeTrend (plus its `span` ternary by hand), and CalendarProjection.
  - **CalendarProjection.swift is outside this PR's screens** (L10N-03a's, on main): call sites only,
    13 lines. Its lookups slow down with this PR's larger catalog too (Calendar stage 11.4 ms on main,
    20.5 ms here), and main itself has little margin. Flagged in the report.
  - Left direct (rare, mixed `Int` arguments): `completionDetail(Int, Int)`, `heavyHeadline(Int, String)`,
    `overlapsWithMore(String, Int)`.
- Every converted `String`-argument function was checked to interpolate its arguments as they are
  (a script printed each `defaultValue`): the placeholder method depends on that.
- `ToDoItem.markedDoneText`'s comment kept accurate: `L10n.string` keys its cache by locale.
- Local checks: Linux probe of the fill against `String(format:)`, 1,575 format/argument pairs
  (positional `%2$@`, repeated `%1$@`, `%%`, placeholders, `%`, combining marks, emoji, RTL in the
  arguments): 0 mismatches. `L10n+Lookup.swift` compiled with `-swift-version 6
  -strict-concurrency=complete` against Linux stand-ins for `LocalizedStringResource`: clean, and the
  stand-in run shows the fill leaving an argument's U+E001 alone. `swiftc -parse`: every changed
  file clean. Literal, catalog, DEBUG-only, view-body and widget-isolation gates: PASS. Hygiene greps
  (`print(`, `Task.detached`, `nonisolated(unsafe)`, `uniqueKeysWithValues`): no match.
- New hosted test `L10nLookupTests` (30 keys: 13 plain, 8 one-argument, 4 two-argument, 2
  three-argument, 3 plural): byte-for-byte equal to `String(localized:)`, first call and cached.

## 6. The right-to-left fix (`795e635`)

- An argument, or a key's text, with any right-to-left character (U+0590-08FF, FB1D-FDFF,
  FE70-FEFF, 10800-10FFF, 1E800-1EFFF: a superset of bidi classes R, AL and the Arabic digits) or
  any bidi control (`isBidiControl`) goes to `String(localized:)` uncached, exactly as before.
  Left-to-right arguments keep the cached path. No-argument keys and plurals cache the full text
  `String(localized:)` returned, so they were never affected.
- The guard's absence is already shown to fail the test (36976127452 ran the code without it). With
  it, the PR run must pass `L10nLookupTests`.
- Test arguments widened: Arabic, an LRM, an isolate pair, Arabic digits.
- Local: a Linux stand-in for `String(localized:)` that isolates as iOS 26.5 did: 2,020 checks, 0
  differences, Hebrew comes back isolated. `swiftc -parse`, literal, catalog, DEBUG-only and widget
  gates: clean.
- Finding for the L10N-03b report: this isolation is not new with my change. The sweep itself moved
  these phrases from string interpolation to `String(localized:)`, so a right-to-left Canvas name
  in them now carries U+2068/U+2069 that pre-sweep main did not emit. Left-to-right text is
  byte-identical. Recorded as an open item for the owner (it is arguably the correct rendering).
